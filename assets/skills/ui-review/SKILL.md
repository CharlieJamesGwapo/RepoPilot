# UI review

## Purpose

Review an implemented interface for task clarity, consistency, states, and practical usability.

## Workflow

1. Confirm the intended audience, primary task, and constraints before evaluating the screen.
2. Inspect the rendered interface alongside the actual implementation and existing patterns.
3. Check information hierarchy, labels, action placement, and consistency between screens.
4. Try the primary flow and recovery from empty, loading, invalid, and failed states.
5. Check keyboard navigation, focus visibility, semantics, and responsive behavior.
6. Use realistic content and long strings rather than only ideal demonstration data.
7. Distinguish measured failures and task obstacles from subjective visual preferences.
8. Record concrete findings with a screenshot or location, trigger, impact, and suggested change.
9. Prioritize corrections that restore task completion before cosmetic refinements.
10. Recheck changed states and summarize tested conditions without a blanket quality guarantee.

## Deliverable

A prioritized UI review grounded in observed behavior and specific improvement suggestions.

## Evidence

Each reported issue can be located and reproduced; claims are limited to the tested flows and states.

Record the relevant inputs, observed results, and limits of the check.
Do not substitute confidence, a screenshot alone, or a prior run for current evidence.
